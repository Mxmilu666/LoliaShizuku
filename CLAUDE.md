# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

LoliaShizuku (「ロリア・雫」) is a third-party desktop client for Lolia FRP, built with [Wails v3](https://v3.wails.io) (pinned to `v3.0.0-beta.28`) (Go backend + Vue 3 frontend in a single native window). It handles OAuth login, a dashboard for user/traffic/tunnel data, and managing a local `frpc` runner process (install/update/start/stop with live logs).

## Commands

All commands run from the repository root unless noted.

```bash
wails3 dev         # Run full app in dev mode (auto-runs `bun install`, regenerates bindings, hot-reloads frontend + Go)
wails3 build       # Production build → bin/  (Linux: add EXTRA_TAGS=gtk3)
wails3 package     # .app bundle / NSIS installer / Linux packages
wails3 generate bindings -clean=true -ts -i   # Regenerate frontend/bindings after changing exported service methods
```

Frontend-only (from `frontend/`):

```bash
bun install
bun run dev        # Vite dev server
bun run build      # vue-tsc typecheck implied via build; outputs to frontend/dist
```

There is **no test suite** and no separate lint step in this repo. Use `go vet ./...` and `go build ./...` to sanity-check Go changes; the frontend `bun run build` doubles as a typecheck.

### Prerequisites

- Go `>= 1.27`, Bun, and the Wails v3 CLI (`go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.28`; keep it in sync with `go.mod`).
- `CGO_ENABLED=1` is required for builds (WebView bindings) — see `.github/workflows/release.yml`.
- Build orchestration lives in `Taskfile.yml` + `build/Taskfile.yml` + `build/<os>/Taskfile.yml`; app metadata in `build/config.yml`. `EXTRA_LDFLAGS` / `EXTRA_TAGS` vars are appended to production `go build`.
- Linux uses GTK3 / WebKitGTK 4.1 via the `gtk3` build tag (v3's default is GTK4 / WebKitGTK 6.0).

## Architecture

### Backend ↔ Frontend bridge (the core pattern)

The frontend never makes HTTP calls to the Lolia API directly. Instead, Go service structs are registered as **services** in `main.go` (`Services: []application.Service{application.NewService(...)}`), and Wails generates TS bindings (interfaces mode, `-ts -i`) under `frontend/bindings/github.com/Mxmilu666/LoliaShizuku/backend/...`. Every exported method on a service struct becomes callable from JS (lifecycle hooks like `ServiceStartup` are excluded).

The frontend imports generated bindings, e.g. `import { CenterService } from "../../bindings/github.com/Mxmilu666/LoliaShizuku/backend/services"`. `frontend/src/services/center.ts` and `frontend/src/services/frpc.ts` wrap them, normalize errors (Chinese messages), and re-export hand-written typed interfaces. Window/browser/app runtime APIs come from `@wailsio/runtime` (`Window`, `Browser`, `Application`, `Events`), whose npm version must match the Go module version.

**When you add or change an exported Go service method, the bindings in `frontend/bindings/` are regenerated by `wails3 dev`/`wails3 build`** (or `wails3 generate bindings -clean=true -ts -i`). Don't hand-edit them.

Backend → frontend push uses Wails events: `System().Emit("window_changed", ...)` in `system_service.go` (wraps `application.Get().Event.Emit`), consumed via `Events.On("window_changed", (e) => e.data ...)` in `AppHeader.vue`. In v3 the callback receives a `WailsEvent`; the payload is `event.data`. This is how the frameless custom title bar stays in sync.

### Bound Go services (`backend/services/`)

- `App` (`backend/app.go`) — config CRUD (`GetConfigJSON`/`UpdateConfig`/`ResetConfig`), version info; `ServiceStartup` hook.
- `PreferencesService` — window size persistence.
- `TokenService` — `HasOAuthToken` and token presence checks (used by the router auth guard).
- `CenterService` — the main API client (dashboard, tunnels, traffic) **and** the local frpc runner lifecycle (`StartRunner`/`StopRunner`/`GetRunnerRuntimeStatus`). Runner state is mutex-guarded (`runnerMu`); logs are ring-buffered to `runnerLogMaxLines` (300). The runner is force-stopped in the application `OnShutdown` hook (closing the last window quits the app on all platforms).
- `FrpcService` — downloads/installs/updates/removes the `frpc` binary from GitHub releases, with configurable download mirrors.
- `SystemColorService` — dynamic color ("莫奈取色") inputs: `GetWallpaperPixels` reads the desktop wallpaper (macOS `NSWorkspace` + `sips` for HEIC, Windows `SystemParametersInfo`, Linux GNOME `gsettings`; split across `wallpaper_<os>.go`) and returns a ≤128px RGBA sample; `GetSystemAccentColor` falls back to the OS accent. The frontend (`services/dynamicColor.ts`) extracts the seed with `sourceColorFromImageBytes` (same Celebi + Score pipeline as Android) and caches it in `localStorage` (`lolia.dynamicSeed`). On Android the seed comes from the template's JS bridge `window.wails.getDynamicSeed()` (`WailsJSBridge.java`: Android 12+ `system_accent1_500` — TonalSpot only uses the seed's hue, so this reproduces the system palette; 8.1–11 the wallpaper's primary color) via `utils/platform.ts` `getAndroidDynamicSeed`, re-read when the app returns to the foreground.
- `systemService` (`services.System()`, singleton, not bound) — holds the main `*application.WebviewWindow` (set in `main.go`), polls window state in a loop, persists size/maximised, and emits `window_changed`.

### HTTP / API layer

- `backend/httpclient/client.go` — generic client that unwraps the Lolia API envelope (`{code, status, msg, data}`), injects the OAuth bearer token via a `GetAccessToken` callback, and invokes `OnUnauthorized` (which clears the stored token) on 401. Returns typed `*APIError`.
- `backend/api/center.go` — typed endpoint methods returning models from `backend/models/`.
- `backend/api/github_release.go` — GitHub release lookups for frpc.

### OAuth flow

Login is **Authorization Code + PKCE** with a loopback callback, or **Device Authorization** (RFC 8628, `oauth_device.go`: `TokenService.StartDeviceLogin` returns the user code / verification URI, `WaitDeviceLogin` polls via `oauth2.Config.DeviceAccessToken` until approved, denied or expired, `CancelDeviceLogin` stops it; the OAuth page shows the code and, on desktop, a QR code of `verification_uri_complete`). Files: `oauth_flow.go`, `oauth_device.go`, `oauth_token.go`, `token_service.go`, `token_store.go`. Tokens are stored in the OS **keyring** (`zalando/go-keyring`) under service `LoliaShizuku`, key `oauth_token`. Default callback listens on `http://localhost:1145`. `loadValidOAuthToken` (`oauth_token.go`) handles refresh under a mutex — the center revokes the previous access token on every refresh (access 24h, refresh token fixed for 30 days from login), so concurrent refreshes would revoke each other. `httpclient` refreshes once and retries on a 401 (`RefreshAccessToken`), and clears the token only if the retry is rejected too. A rejected refresh token (`invalid_grant`) clears the token (`errOAuthLoginRequired`) and the router guard (`frontend/src/router/index.ts` `beforeEach`) redirects to `/oauth`; network errors during refresh keep the token, and `HasOAuthToken` still reports logged in.

### Configuration (two distinct stores — don't confuse them)

1. **App config** (`backend/config/config.go`) — JSON `Config` struct (theme, window, advanced) stored on disk via the `Manager`. Loaded *before* the window opens in `main.go` to restore window size.
2. **frpc state** — under `os.UserConfigDir()/LoliaShizuku/userdata/frpc/`: `bin/` (binary), `downloads/` (cache), `installed.json` (install state), `settings.json` (mirror settings).

Many behaviors are overridable by env vars (API base URL, OAuth client/URLs, frpc repo, HTTP UA) — see the table in `README.md`. Defaults point at `api.lolia.link` / `dash.lolia.link` and the `Lolia-FRP/lolia-frp` GitHub repo.

### Frontend (`frontend/src/`)

Vue 3 + TypeScript + Vuetify 4 (pinned `4.2.4`, Material Design 3 blueprint) + Pinia + vue-router. Use MD3 typography classes (`text-headline-small`, `text-title-medium`, `text-body-medium`, `text-label-small`…); the MD2 classes (`text-h6`, `text-caption`…) no longer exist in v4. Colors follow MD3 dynamic color: `plugins/theme.ts` generates every color role from the accent seed with `@material/material-color-utilities` (HCT, `SchemeTonalSpot`) and writes them into the Vuetify themes. Note Vuetify's `surface-variant`/`on-surface-variant` mean *inverse* surface (tooltips/snackbars), so MD3's onSurfaceVariant is exposed as `md-on-surface-variant`. `assets/css/style.css` aliases the roles as CSS vars (`--md-surface-container-*`, `--md-primary-container`, `--md-secondary-container`, `--md-on-surface-variant`, `--md-outline-variant`…); never hand-mix colors — use the role that the MD3 component spec prescribes (filled card = surface-container-highest, outlined card = surface + outline-variant, selected/tonal = secondary-container, dialogs = surface-container-high). The same file defines shared MD3 building blocks used by every page — `md-page` / `md-page-header`, `md-card-filled` / `md-card-outlined` / `md-card-primary`, `md-stat`, `md-icon-container`, `md-kv-row`, `md-dialog`, `md-on-surface-variant`, `md-mono` — prefer these over ad-hoc `v-card elevation` styling. Tunnel display helpers (status/type meta, address formatting, clipboard) live in `src/utils/tunnel.ts`; always format dates with `utils/format.ts` `formatDateTime` (fixed zh-CN — `toLocaleString()` follows the system language, e.g. en-US on Android). Home announcements come from `CenterService.GetHomeAnnouncements` (center `/user/announcements/top` + `/board`); content is Markdown rendered by `utils/announcement.ts` (markdown-it + DOMPurify, same allow-list as the web dashboard) via `AnnouncementContent.vue`, which opens links in the system browser. `style.css` also restores v3's grid (legacy mode), container widths and CSS reset; `main.ts` restores v3 breakpoints. Vite alias `@` → `frontend/src`. Theme (`plugins/theme.ts`, light/dark/system) is set up in `main.ts` and synced with system preference via `matchMedia`; the choice is persisted in `localStorage` (`lolia.theme`), separate from the Go-side config.

- `pages/` — one folder per route: `home`, `oauth`, `tunnels`, `runner`, `settings`. Routes are lazy-loaded in `router/index.ts`, guarded by OAuth token presence.
- `services/` — typed wrappers over Wails bindings (`center.ts`, `frpc.ts`).
- `stores/` — Pinia (`frpcInstall.ts` for install progress, `globalLoading.ts`).
- The window is **frameless** (`Frameless: true` in `main.go`); `AppHeader.vue` is the custom draggable title bar.

## Conventions

- Code comments and user-facing strings are frequently in **Chinese**; match the surrounding style.
- Platform-specific process handling lives in `process_attr_windows.go` / `process_attr_other.go` (build-tag split) — keep both in sync when changing runner process spawning.
- Android (experimental) shares the desktop runner: frpc is downloaded in-app and spawned as a child process. This only works because `build/android/app/build.gradle` sets `targetSdk 28` (like Termux; API 29+ forbids exec from app data) — don't raise it. Platform splits use `//go:build android` / `!android`: `runner_hooks_*` (foreground service). frpc is always started with `frpc -t id:token` on every platform (`runner_args.go`) — never rewrite or write tunnel config files, `secret_store_*` (keyring vs Wails `Android.Secure*`), `open_url_*`, and root `main_android.go` / `main_desktop.go` (Android points `XDG_CONFIG_HOME` at `Android.StoragePath()`; Wails' build overlay registers `main`, so don't call `RegisterAndroidMain` yourself). Note `android` also satisfies the `linux` build tag. Launcher icons are generated from `build/appicon.png` by `build/android/scripts/icons` (not committed).
- Frontend mobile layout: `utils/platform.ts` `isMobile` (checks the Android JS bridge / User-Agent too — Wails injects `window._wails.environment` only after page load) adds `is-mobile` to `<html>` and switches to MD3 mobile patterns: small top app bar with the route's `meta.title` (pages put actions into it via `<Teleport defer to="#app-bar-actions">`), bottom navigation bar (`MobileNavBar.vue`), primary actions as `MobileFab.vue`, full-screen dialogs, settings as list → sub-page (`/settings?panel=…`, works with the Android back gesture). In-page `.md-page-header` is hidden on mobile. Android system bar colors follow the theme through the template's `window.wails.setSystemBars` (`WailsJSBridge.java`). Vuetify typography utilities are `!important` inside a CSS layer, so unlayered `!important` overrides lose — switch the class in the template instead. To check the real Android UI without logging in, build a debug APK whose frontend uses the mock bindings and run it in the emulator.
- Version is centralized in `backend/version/version.go` (used for the HTTP User-Agent and update checks).
